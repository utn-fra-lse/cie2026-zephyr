\resumenES{El firmware para microcontroladores suele quedar atado al kit de desarrollo de cada fabricante, lo que encarece la migración entre plataformas ante faltantes de componentes o cambios de requerimientos. Esta nota técnica analiza los mecanismos con los que Zephyr, un sistema operativo de tiempo real de código abierto alojado por la Linux Foundation, desacopla la aplicación del hardware: el devicetree resuelto en tiempo de compilación, el modelo de dispositivos con interfaces de programación estandarizadas y el sistema de configuración Kconfig. Para evaluarlos se desarrollaron dos aplicaciones, una de entradas y salidas digitales con interrupciones y otra de lectura de acelerómetros por I2C, que se compilaron sin modificar su código fuente para diez placas de cinco fabricantes de silicio y tres arquitecturas de procesador. Las diferencias entre plataformas quedaron confinadas a archivos de superposición de devicetree de pocas líneas, y el reemplazo de un acelerómetro integrado en la placa por uno externo se resolvió con el mismo mecanismo. Se informa el uso de memoria de cada plataforma y se discuten las limitaciones del enfoque. Se concluye que Zephyr permite tratar la placa como un parámetro de compilación, con beneficios para el desarrollo de productos y para la enseñanza.}
\keywordsES{sistemas embebidos; sistema operativo de tiempo real; Zephyr; devicetree; portabilidad}

\resumenEN{Microcontroller firmware is usually tied to each vendor's software development kit, which makes migrating between platforms costly when components become scarce or requirements change. This technical note analyzes the mechanisms through which Zephyr, an open-source real-time operating system hosted by the Linux Foundation, decouples the application from the hardware: a devicetree resolved at build time, a device model with standardized programming interfaces, and the Kconfig configuration system. To evaluate them, two example applications were developed, one for digital input and output with interrupts and one for reading accelerometers over I2C, and they were built without modifying their source code for ten boards from five silicon vendors and three processor architectures. Platform differences were confined to short devicetree overlay files, and replacing an on-board accelerometer with an external one was handled with the same mechanism. Memory usage on each platform is reported, and the limitations of the approach are discussed. It is concluded that Zephyr makes it possible to treat the board as a build parameter, with benefits for product development and for engineering education.}
\keywordsEN{embedded systems; real-time operating system; Zephyr; devicetree; portability}
